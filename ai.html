Transparency

How we use AI

A short account of what a model sees, who hosts it, and what StaffMatch keeps. Last updated September 6, 2026.

What a model does — and what it does not

StaffMatch uses a language model for one step: turning uploaded document text into structured fields. Matching people to projects is not a model call.

  • Extract. When you add a resume, proposal, or RFP, we pull the text from the file and send that text to a model so it can fill structured fields (for example skills, roles, and requirements). The rest of the product works from those fields.
  • Match. Ranking compares keywords and overlapping fields with a deterministic score. It does not ask a model who is “best.”

Matching output is assistive. You remain responsible for staffing and proposal decisions.

Provider and model

Extract requests go through OpenRouter. The model ID is set in server configuration, not in this marketing site.

Right now we try a free OpenRouter model first. If that route is rate-limited, we fall back to inclusionai/ling-3.0-flash, a paid OpenRouter route.

Training

StaffMatch does not train its own models on your documents.

OpenRouter is a routing layer in front of an upstream model host. We do not control OpenRouter’s account settings or that host’s training policy, and we cannot promise either from this page.

OpenRouter’s public documentation (as of this writing) says:

  • They do not store prompt or response content unless an account opts in. They do store request metadata such as token counts, latency, and model. See Data Collection.
  • They do not use inputs or outputs to train OpenRouter’s own models. See their Privacy Policy.
  • Downstream hosts have their own logging and training rules. Free endpoints, in particular, may allow a host to train on requests. OpenRouter documents this on Provider Logging and on each model page.

If you need a no-training or zero-retention path, that has to be confirmed on OpenRouter and the chosen host. We will not claim it here.

What StaffMatch keeps

  • We store the structured extract in Postgres.
  • We do not retain original uploaded PDFs by default.
  • If a local JSON file is written on the app server, that path sits on Render’s disk. On the free plan that disk is ephemeral — files there are lost on restart, redeploy, or spin-down.

We do not sell your information. Account passwords go only to Supabase Auth — never by email and never through this site’s marketing forms. See the Pilot Terms.
